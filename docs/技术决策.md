# 技术决策与踩坑记录

这不是 API 文档，是**「为什么代码长这样」**。里面每一条都对应一次真实故障，
数字（分辨率、码率、超时、退避秒数）都是实测值。

**改 `server.js` 之前先读这一篇。** 凡是标了 🔴 的，删掉之后 YouTube 那边立刻坏。

---

## 1. 取流链路：403 的三道关

### 1.1 🔴 `playerClient` 默认留空，不要写死客户端组合

`clientArgs()` 默认返回空数组 = 不向 yt-dlp 声明 `player_client`，由它自己挑。

历史坑：曾经默认写死 `tv,web_safari,mweb`，理由是「多客户端组合能同时拿到有效流与匹配的
PO Token」。2026-10 之后这套组合反过来成了故障源，同一条视频实测：

| 客户端 | 表现 |
|---|---|
| `tv` | 直接 UNPLAYABLE（`The page needs to be reloaded.`） |
| `web_safari` | 被强制 SABR 流，格式没有可用 URL |
| `mweb` | 同上，偶尔解析出 1080p，一取流就 403 |

于是出现「解析正常、下载到 20 MB 突然 403」。把 `player_client` 去掉后，同一条视频
1080p60 H.264 全程 418 MB 正常下完。

**这类列表的正确维护者是 yt-dlp 自己**（它跟着 YouTube 改），不是我们。设置里仍可手填，
但只有用户明确填写时才传参。

另外有个配置迁移：老版本把 `tv,web_safari,mweb` 写进了用户的 `config.json`，光改默认值没用，
所以 `migrateConfig()` 做了一次等比迁移——**只认集合完全相同**（忽略顺序/空格/大小写），
用户自己填的组合一律不动。

### 1.2 🔴 PO Token 优先 script 模式，不用 HTTP 模式

`potArgs()` 的两种模式：

- **A. HTTP 模式**（`youtubepot-bgutilhttp`）：向本地服务的 `/ping`、`/get_pot` 发请求。
  缺点致命：这些请求走 yt-dlp 自己的网络栈，一旦设了 `--proxy`，**连 127.0.0.1 都会被代理拦截**
  （代理软件默认不转发回环地址），token 必取不到。这就是「挂了 VPN 反而更差」的原因。
- **B. script 模式**（`youtubepot-bgutilscript`）：直接 fork 本地
  `runtime/pot-server/build/generate_once.js` 生成令牌，**全程不经过网络**，不受代理影响。

所以：`server_home` 存在就用 script 模式，否则才退回 HTTP。

### 1.3 🔴 `potArgList()` 绝不能用「HTTP 探测活着」当前置条件

这是「有时候只解析出最低画质」的根因。

曾经的写法：`if (await potAlive()) args.push(...potArgs())` —— 探 4416 端口，超时 1500ms。
但 script 模式**根本不需要**那个 HTTP 服务，拿它当开关意味着 POT 冷启动 / 繁忙时探测一超时，
令牌参数就被整个丢掉 → YouTube 只回一条 360p 合并流（**format 18**）→ 界面显示「仅 1 档 / 最高 360p」。

修正后的判定顺序：`potScriptReady()`（**纯文件系统判断**）优先 → 再 `potAlive()`。

实测客户端矩阵：

| 场景 | 结果 |
|---|---|
| `web` / `mweb` 无令牌 | 只有 360p（format 18） |
| `web` / `mweb` 有令牌 | 24 个格式，最高 2160p |
| `tv` 单用 | 必报 `The page needs to be reloaded` |

### 1.4 🔴 必须用 pip 版 yt-dlp

`YTDLP_HAS_PLUGIN` 判定条件：`runtime/python/Lib/site-packages/yt_dlp/__init__.py` 存在。

`bin/yt-dlp.exe` 独立 exe **不加载 `yt_dlp_plugins`**，拿不到 PO Token，必然 403 或只有 360p。
所以调用优先级是：`runtime/python`（`python.exe -m yt_dlp`）> `runtime/venv/Scripts/yt-dlp.exe`
> `bin/yt-dlp.exe`。

统一入口 `runYtdlp()`，`YTDLP_PREFIX = ['-m','yt_dlp']` 只在 pip 版时非空。

### 1.5 🔴 `jsRuntimeArgs()` 必须传 `--js-runtimes node:<自带 node>`

缺了它 YouTube 的 JS 签名挑战解不开，**必然 403**。优先用 `runtime/node/node.exe`。

### 1.6 🔴 `childEnv()` 必须清掉宿主注入的 node 环境变量

要删除 `NODE_OPTIONS`、`NODE_PATH` 等。否则 yt-dlp 会调到别的（被包装过的）node，
JS 挑战解密失败，报 `ERR_ACCESS_DENIED ... node-safe-delete-shim.cjs`。

同时：未配置代理时还要删掉 6 个代理变量（`HTTP_PROXY`/`HTTPS_PROXY`/`ALL_PROXY` 的大小写共 6 个），
并把自带的 node 目录前置到 `PATH`。

### 1.7 `ensurePotService()` 负责自愈

启动时与解析前各检查一次：script 模式不可用、HTTP 服务也没在跑时，用**隐藏窗口**
（`windowsHide: true`）拉起 `runtime/pot-server/build/main.js --port 4416`，最多等 8 秒。

防的是「启动器漏拉」「POT 中途崩了」这类情况——以前一旦如此，解析会**静默**降级到 360p，
用户完全看不出哪里不对。

## 2. 网络与代理

### 2.1 🔴 网络要自适应，别假定形态

2026-09-29 的教训：前一天直连 YouTube 还能通，第二天就不通了。而程序没配代理时
yt-dlp 裸连 = **黑洞，一路等到超时**，表现就是「解析半天出不来」。

`resolveProxy()` 的顺序：

1. 用户配置（`config.proxy`）
2. 直连可用（`tcpReachable` 到 YouTube）
3. 自动探测本机代理（`probeProxies()` 遍历常见端口：7890/7897/7898/10809/10808/1080/1081/
   2080/2081/8080/8888/1087/20171/33210/4780/7078/9910/10090/10091/10080/2334）
4. 判定不可达

探测用 `proxyTunnelOk()`：**发真实 CONNECT 请求，拿到 `200 Connection established` 才算通**。
只检查端口开着是不够的（很多端口是别的服务）。

### 2.2 🔴 `AUTO_PROXY` 必须全链路生效，尤其 `childEnv()`

`generate_once.js` 是个 **node 程序，自己不读 yt-dlp 的 `--proxy`**，只认环境变量。
实测直连被墙时：不设变量 → 卡死 30 秒以上；设 `HTTPS_PROXY` → 16 秒出令牌。

所以有代理时要设 `HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY`
加 `NO_PROXY=127.0.0.1,localhost,::1`（回环地址不能被代理拦）。

`buildArgs()` 里也必须写 `const useProxy = c.proxy || AUTO_PROXY`，否则会出现
**「解析能用（自动走了代理）但下载卡死」**——因为下载是另一条独立路径。

### 2.3 升级 yt-dlp 时要去掉代理变量

`/api/update-ytdlp` 走的是
`python -m pip install --upgrade yt-dlp bgutil-ytdlp-pot-provider -i https://mirrors.aliyun.com/pypi/simple/`，
这一步必须**清空代理环境变量**（否则 pip 连镜像也会走代理，慢或失败）。`envWithoutProxy()` 负责这个。

## 3. 音轨：原声 vs 自动配音（2026-10-27 修复）

### 3.1 现象

成品画面是原片，声音却是别的语言（实测出现过乌克兰语、阿拉伯语配音）。

### 3.2 根因

YouTube 会给视频下发**几十条自动配音轨**（实测一条视频 132 条音轨 / 20+ 语种），
而且**配音轨与原声轨码率只差 1bps**（原声 `en-US` 129.476k vs `uk` 129.477k）。
任何拿 `br`/`tbr` 决胜的排序都会**稳定挑中配音轨**。

而 yt-dlp 的 `-S` 排序里，用户给的字段会排在默认排序（含 `lang`）之前，
所以旧代码 `-S res:1080,vcodec:h264,acodec:aac,br` 里 `br` 先做决定 → 恒定选中配音轨。

### 3.3 修法（三段都要有，少一段就复发）

1. **排序**：把 `lang` 放在 `acodec`/`br` 之前 → `-S res:1080,lang,acodec:aac,br`
   `lang` 映射到 `format.language_preference`，YouTube 提取器的取值是
   **原声 10 / 默认轨 5 / 普通配音 -1 / 描述性配音 -10**，与具体语种无关，
   所以不用写死 `en`，任何语种的源视频都优先取原声。
2. **过滤**：`-f` 的音频部分一律写 `ba[language_preference>0]`，兜底 `/ba/b`。
3. **视频侧必须用 `bv`，绝不能用 `bv*`**：360p 合流格式 `18` 自带一条**自动配音**音轨
   （实测 `language='ar'`），它的 tbr(427) 远高于同分辨率纯视频格式，一旦排序键里出现
   `br`/`tbr`，`bv*` 就会把它选成「最佳视频」，配音随画面直接进成品。
   老视频只有合流格式时，由末尾的 `b[height<=H]` 兜底。

`AUDIO-MP3` / `AUDIO-NATIVE` 两条纯音频分支同样过滤。

### 3.4 验证与补救

验证看流语言标签：

```bash
ffmpeg -i output.mp4
# (eng) = 原声；(ukr) (ara) 等 = 配音
```

mp4 的流语言标签来自 yt-dlp 合并时各 format 的 `language` 字段。

已串台的旧文件**不用重下整个视频**，只补原声音轨再合成：

```bash
ffmpeg -i old.mp4 -i audio.m4a -map 0 -map -0:a -map 1:a:0 -map_metadata 0 -c copy fixed.mp4
```

（实测用它修好过一条 4K VP9 视频：画面原样保留，音频从 ukr 换成 eng。）

## 4. 进度与产物识别

### 4.1 进度解析

`--newline --progress --progress-template "download:DL:%(progress.status)s|..."` 输出结构化行，
外加正则双保险解析传统百分比行。

### 4.2 🔴 `findProducedFile()` 兜底不能删

清理临时文件时被安全软件/沙箱拦截，yt-dlp 退出码会是 1，但文件其实已经下好了。
靠它按「最近修改的媒体文件」兜底，避免误报失败。

### 4.3 成品识别要排除中间分流

yt-dlp 的中间文件形如 `[id].f160.mp4`、`[id].f140-19.m4a`。
**格式 id 可能带 `-`/`_`/`+`**，正则是：

```
/\.f[0-9A-Za-z_+\-]+\.[A-Za-z0-9]+$/
```

否则会把音频分流误报成成品。

### 4.4 封面必须 `--convert-thumbnails jpg`

YouTube 现在多数封面是 `.webp`，剪映等软件不认。该转换器是 yt-dlp 自带的纯 JS 实现，
**不需要 ffmpeg**。转 mp3 并嵌封面时，也要先把封面转好，否则 `--embed-thumbnail` 会失败。

### 4.5 任务级「三态开关」

`wantThumbnail` 的取值语义：`null` = 跟随全局 `writeThumbnail`，`true`/`false` = 本任务单独指定。
**不要用 `false` 当默认值**——否则分不清「用户明确取消」和「用户没表态」。

## 5. 报错与重试

### 5.1 🔴 报错要分类，别一律重试

`isFatalError()`：网络类、内容类（`Unsupported URL`、视频不可用、私享视频）立即停；
但 **PO Token 脚本超时不算致命**（属抖动，重试有意义）。另有**总时间预算 150 秒**。

实测效果：坏代理 4 秒报错（原来重试三轮）、无效链接 8.7 秒（原来 16.7 秒）。

### 5.2 风控退避重试

`isBotCheck()` 命中（`Sign in to confirm you're not a bot`）时：

| 路径 | 第 1 次重试 | 第 2 次重试 |
|---|---|---|
| 下载 | 等 **30 秒**，换 `default` 客户端 | 等 **75 秒**，换 `tv_embedded,web_embedded` |
| 解析 | 三种策略全被挡下后等 **20 秒**再试一轮 | — |

等待期间状态置 `queued` + 明确 stage 文案，否则「排队中」看着像卡住。

`buildArgs()` 支持任务级 `t.clientOverride` / `t.cookieOverride`，重跑时清掉 `error` / `errorHint`。
另有 `t.noClientArgs` 开关：设置里若留着旧的自定义组合，`clientOverride=''` 会被当成「没设」
而回落，必须要一个**显式开关**才能彻底不声明。

### 5.3 🔴 风控先查版本，再查 IP

2026-10-16 初判成「按出口 IP 的间歇性风控」，只对了一半。2026-10-21 用户换线路仍失败，
把 yt-dlp 从 `2026.07.04` 升到 `2026.08.19` 后，**同一条链接三种客户端组合立刻全通**。

正确顺序：**① 看版本旧不旧（版本号就是发布日期，超过 45 天就该升级）→ ② 全客户端矩阵判断是否
IP 级 → ③ 再考虑 cookies**。

`/api/env` 返回 `ytdlp.ageDays`，前端超过 45 天显示可点的「N 天未更新」标签。

### 5.4 🔴 `yt-dlp -U` 对 pip 版无效

它只打印一句「请用 pip 更新」，**退出码却是 0**。所以升级必须走
`python -m pip install --upgrade`，不能调 `-U`。

### 5.5 报错要翻译成人话

`friendlyError()`：yt-dlp 的原始报错后面挂着一串 GitHub issue 链接，等于没说。
按类型给「可能原因 + 具体动作」（风控 / 403 / 无效链接 / 视频不可用 / 网络不通），
**认不出来就不硬编，返回空串**。

界面上人话提示放显眼处，原始报错折叠进「原始报错（排查用）」，两边都不丢。

## 6. Windows 细节

### 6.1 🔴 `.bat` 必须是 CRLF + 纯 ASCII + 无 BOM

- **LF 行尾**会让 cmd.exe 解析异常
- **BOM** 会把首行 `@echo off` 变成乱码
- 所以 bat 里**不要写中文提示**（chcp 时机难控）
- 不要用 `setlocal enabledelayedexpansion`
- `start` 的第一个引号参数会被当成窗口标题，必须写成 `start "" /min "路径"`

仓库的 `.gitattributes` 已经把 `*.bat`/`*.vbs` 锁成 `eol=crlf`，别改成别的。

### 6.2 🔴 启动器不要多拉窗口

程序走 script 模式取令牌，**根本不需要 4416 的 HTTP 服务**（实测停掉 4416 依然拿到 24 个格式 /
最高 2160p）。所以 `启动下载器.bat` 里删掉了 POT 启动块（原来 `start "POT" /min` 会多弹一个
控制台窗口）和提前开浏览器那行（与端口监听竞态）。

现在只在前台跑 `node server.js`，**bat 的控制台就是服务控制台**，全脚本零 `start`。
浏览器由 `server.js` 在 `listen()` 回调里自己开；script 模式万一不可用，
`ensurePotService()` 用隐藏窗口兜底。

> 验证窗口数要用 Win32 `EnumWindows` + `IsWindowVisible` 枚举顶层窗口，再配 `tasklist` 映射
> PID→进程名。**按 node.exe 的 PID 找不到控制台窗口**——它由 conhost / Windows Terminal 承载，
> 类名是 `ConsoleWindowClass` / `PseudoConsoleWindow`。

### 6.3 🔴 打开文件夹必须走 `cmd /c start "" explorer.exe /select,<file>`

`spawn('explorer.exe', [...], { windowsHide: true })` 在部分环境**窗口不出现**（退出码还恒为 1）。
统一走 `openFolder()`，内部 4 种方式依次兜底，`windowsHide` 一律去掉，加 `stdio: 'ignore'`。
前端调用失败时 toast 反馈，并把路径写进剪贴板兜底。

打开单个文件（如封面）走 `openFile()` + `/api/open-file`。

### 6.4 🔴 桌面快捷方式（.lnk）绝不要手写二进制

2026-09-17 的坑：手写版只写了 StringData + EnvironmentVariableDataBlock，没写
`LinkTargetIDList` / `LinkInfo` → 文件里**根本没有任何「目标」信息** → 桌面图标变成通用白纸、
**双击毫无反应**。`EnvironmentVariableDataBlock` 不是目标本体，它只是 IDList 里 `EXP_SZ_LINK`
的补充。

正确做法用 `tools/make_shortcut.py`：ctypes 调进程内 COM `IShellLinkW` + `IPersistFile::Save`，
让 Windows 自己写。另：`FileAttributes` 必须是 `0x20`(ARCHIVE)。

**验证必须让 Windows 判**（`IPersistFile::Load` + `IShellLinkW::GetPath` 回读，或
`ShellExecuteW` 返回 > 32）——自己解析自己的产物是假阳性（自洽但无效）。

图标用 `tools/make_icon.py` 生成，**每个尺寸单独按档位绘制**，别用 1024 大图缩
（24px 以下会糊成一团；16px 要放弃圆盘轮廓、让粗箭头占满）。

### 6.5 进程内 COM 可用，PowerShell 层的 COM 被拦

`New-Object -ComObject` ✗，但 Python ctypes 直接 `CoCreateInstance` ✅（生成 .lnk、读文件信息都靠它）。

## 7. 便携化

### 7.1 🔴 `runtime/venv` 不可移植

venv 里 `Scripts/*.exe` 是 pip 生成的启动器，**内嵌创建时的 python.exe 绝对路径**
（以及 `pyvenv.cfg` 里的 `home`）。整个目录拷到别的电脑就跑不起来。

### 7.2 现在的方案：自带 CPython + `-m yt_dlp`

`runtime/python`（随包标准 CPython）+ 把 venv 的 site-packages 合并进去，
统一用 `python.exe -m yt_dlp` 调用，**路径完全跟随目录**，拷到哪都能跑。

判定条件 `PY_HAS_YTDLP` = 存在 `runtime/python/Lib/site-packages/yt_dlp/__init__.py`。

### 7.3 打包清单

排除：`runtime/venv`、`.dsh`、`downloads/*`、`config.json`、`_diag`、`_tmp_fix`、`.git`。
生成一份 `使用说明.txt`（**UTF-8 BOM + CRLF**，Windows 记事本才不会乱码）。

实测：274.5 MB → **93.3 MB zip**，8474 个文件。

### 7.4 🔴 打包后必须「换路径」实测

解压到**另一个目录**，用 `.bat` 启动，确认：

1. `/api/env` 里的 `ytdlp.path` 指向**解压目录内**的 python
2. 跑一次**解析 + 下载**

只测解析会漏——下载走 `spawn` 那条独立路径。

## 8. 其它约定

- **零外部依赖**：`server.js` 只用 Node 内置模块；所有二进制随包自带
- **零外部资源前端**：不引 CDN、不用 Web Font，样式全部内联
- **视觉**：深色主题、卡片式、强调色 YouTube 红 `#ff3b5c`
- **命令行输出全中文**；界面文案给可操作的排查步骤，不抛原始报错
- 服务只绑 `127.0.0.1`；端口可用环境变量 `PORT` 覆盖（默认 8808）
- `ensureDirs()` 启动时确保 `bin/`、`public/`、下载目录存在
