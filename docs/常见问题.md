# 排障手册

按**你看到的症状**查。每条都按「现象 → 为什么 → 怎么办」写。

卡住了先跑一次自检，它会把所有依赖项的状态打成一张表：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\check-deps.ps1
```

---

## 一、起不来

### 双击 `启动下载器.bat` 黑窗口一闪就没了

窗口闪一下消失 = 脚本里出错了。改用**命令行**跑，报错才留得住：

```batch
cd /d "解压出来的目录"
node server.js
```

最常见的三种原因：

| 报错里出现 | 原因 | 怎么办 |
|---|---|---|
| `'node' 不是内部或外部命令` | 没找到 Node.js | 装 [Node.js LTS](https://nodejs.org/)，或用便携包（自带 `runtime\node`） |
| `Error: listen EADDRINUSE` | 8808 被占用 | 见下一条 |
| `Cannot find module` | 目录不完整 | 重新解压；源码运行则先跑 `scripts\install-deps.ps1` |

### 提示端口被占用（`EADDRINUSE`）

先看是谁占着：

```powershell
netstat -ano | findstr :8808
# 最后一列就是 PID，然后：
tasklist /FI "PID eq <PID>"
```

多半是**上一次的窗口没关干净**（命令行窗口关了但 node 还在跑）。杀掉它：

```powershell
taskkill /PID <PID> /F
```

或者换个端口启动：

```batch
set PORT=9000
node server.js
```

> 换端口后浏览器地址也要跟着变：`http://127.0.0.1:9000`。

### 浏览器没自动打开

服务其实已经起来了，手动访问 `http://127.0.0.1:8808` 即可。

`server.js` 是在 `listen()` 成功回调里调 `start` 打开浏览器的。如果系统默认浏览器设置了
奇怪的拦截，这一步会静默失败——不影响使用。

### 双击 `.vbs` 备用启动器也没反应

`.vbs` 走的是 `WScript.Shell.Run`，不弹窗口。它失败时**什么提示都不会有**，所以排障时
请用 `.bat` 或命令行，能看见报错。

## 二、解析（粘贴链接后的第一步）

### 只解析出 1 档，最高 360p

**这是 PO Token 没生效的典型症状。** YouTube 对没有令牌的请求只回一条
360p 的合并流（format 18）。

按顺序检查：

1. `runtime\pot-server\build\generate_once.js` 在不在？
   不在 → 便携包解压不完整，或源码运行没跑 `install-deps.ps1`。
2. 用的是 pip 版 yt-dlp 吗？
   `runtime\python\Lib\site-packages\yt_dlp\__init__.py` 是否存在？
   `bin\yt-dlp.exe` 独立版**不加载插件**、拿不到令牌，程序虽然优先用 pip 版，
   但 pip 版缺失时会退回独立版 → 直接掉到 360p。
3. 设置里 `playerClient` 是不是被填了东西？**清空它**。

自检脚本里「PO Token」那一行会直接告诉你结论。

### 一直转圈、半天没结果

**根本原因：直连 YouTube 不通，程序又没有代理可走，于是一路等到超时。**

程序在没配 `proxy` 时会自动探测本机常见代理端口（7890 / 7897 / 7898 / 10809 / 10808 /
1080 / 2080 / 8080 / 8888 / 10090 等 20 多个）。探测方式是**发真实 CONNECT 请求并检查
是否返回 `200 Connection established`**——只看到端口开着不算数。

所以：

- 有代理软件 → 在设置里**手填**地址，比自动探测可靠。常见写法：
  `http://127.0.0.1:7890`（Clash）、`http://127.0.0.1:10809`（v2rayN）
- 没有代理 → 检查一下代理软件的「系统代理」开关，或换个能连的出口

可以用设置里的「测试网络」按钮快速验证，它会分别报告直连与代理的连通性。

### 报「Sign in to confirm you're not a bot」

YouTube 的风控页。**先别急着配 cookies**，正确顺序是：

1. **升级 yt-dlp**（界面上点「更新 yt-dlp」，或看 `/api/env` 里的版本年龄，
   超过 45 天会自动亮黄标）。这一条能解决大多数情况——YouTube 改了校验逻辑，
   旧版 yt-dlp 的签名算法就过不了。
2. 换出口 IP / 换节点。
3. 最后才轮到 cookies。

程序命中这个错误时会**自动退避重试**：第一次等 30 秒换 `default` 客户端，第二次等 75 秒
换内嵌客户端。等的时候状态是「排队中」并写着原因，不是卡死。

### 报错里有一堆 `github.com/yt-dlp/issues/...` 链接

那是 yt-dlp 的原始报错原文，界面已经把它折叠进「原始报错（排查用）」。
看上面那行人话提示就够了；要提交 issue 时再把原文展开复制。

## 三、下载

### 解析成功，但下载到一半 403

情形和「能解析不能下载」不同，这是**取流阶段**被拒。按顺序查：

1. **yt-dlp 版本**（同上，最常见）
2. **代理节点**——有些节点被 YouTube 标记，换一个
3. **`playerClient`**——确认是空的。**不要**手动填 `tv`、`web_safari`、`mweb`，
   这三个客户端当前会被 YouTube 强制降到不可用的 SABR 流，表现就是「前 20 MB 正常，然后 403」

如果 1080p 一直 403，可以先试 **H.264 兼容模式**（设置里切到「兼容优先」）——AV1/VP9
的某些流受风控更严。

### 进度条走完却报「下载失败」

看到过这种情况：文件其实下好了，但**清理临时文件时被杀毒软件/沙箱拦截**，yt-dlp 返回了
非 0 退出码。

程序有兜底：会去下载目录里找最近修改的媒体文件，找到就仍按成功处理。如果确实报了失败，
去下载目录看一眼——文件很可能在那儿。

### 只有画面没声音 / 声音是外语（自动配音）

2026-10-27 已修：YouTube 会给视频下发几十条**自动配音轨**，配音轨和原声轨码率只差
1bps，所以任何按码率决胜的排序都会挑中配音轨。现在的排序键是
`res:H,lang,acodec:aac,br`，`lang` 排在最前面，靠 `language_preference`
（原声 10 / 默认 5 / 普通配音 -1 / 描述性配音 -10）稳定取原声。

**升级到最新版**即可。已经下好的旧文件不必重下整个视频，只补原声音轨再合成：

```bash
# 1. 单独下一条原声音轨
yt-dlp -f "ba[language_preference>0]/ba" -o audio.m4a "视频地址"

# 2. 换掉旧文件里的音轨（画面原样保留）
ffmpeg -i old.mp4 -i audio.m4a -map 0 -map -0:a -map 1:a:0 -map_metadata 0 -c copy fixed.mp4
```

验证音轨语言：

```bash
ffmpeg -i fixed.mp4
# 看 (eng) / (ukr) / (ara) 这类标签，eng 才是原声
```

### 报「You have requested merging of multiple formats but ffmpeg is not installed」

缺 `bin\ffmpeg.exe`。下载地址见 [bin/README.md](../bin/README.md)，
或直接跑：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\install-deps.ps1
```

### 字幕没下全 / 只有自动字幕

`subtitleLangs` 默认 `zh-Hans,zh-CN,zh,en`，按**这个顺序**去要字幕，视频没有对应语言的就跳过。
想要别的语种，在设置里改这一串（逗号分隔）。

注意 YouTube 的「自动生成字幕」和「人工上传字幕」是两套，程序两套都会尝试。

### 封面是 .webp，剪映/PS 打不开

程序已经统一加了 `--convert-thumbnails jpg`，产物是 jpg。如果拿到的是 webp，说明这是
**旧版本**下载的文件，或者转换失败（这个转换器是 yt-dlp 自带的纯 JS 实现，不依赖 ffmpeg）。

## 四、代理相关的怪现象

### 配了代理，解析反而更慢 / 更差

两种可能：

1. **代理地址写错**。认准「HTTP 代理」还是「SOCKS5」前缀：`http://127.0.0.1:7890`、
   `socks5://127.0.0.1:1080`。
2. **PO Token 的 HTTP 退路被代理拦了**。程序默认走**本地脚本模式**生成令牌
   （fork 一个 node 进程），完全不走网络，所以不受影响；只有当脚本模式不可用时才退回
   HTTP 模式去连 `127.0.0.1:4416`——而代理软件通常**不转发回环地址**，这时令牌必取不到。

判断方法：自检脚本里 PO Token 显示「script 模式」就是好的；
显示「HTTP 模式 / 不可用」就别再挂代理折腾了，先修脚本模式。

### 关掉代理软件后程序还是走代理

程序在启动/解析时会探测代理并记住，但**不会写进你的配置**。重启服务即可恢复直连检测。

另外：如果系统里设了 `HTTP_PROXY` / `HTTPS_PROXY` 环境变量，程序在**没配代理**的情况下
会主动清掉它们，避免 yt-dlp 走到黑洞代理上。

## 五、成品与文件

### 下载完了找不到文件在哪

界面上每张完成的卡片都有「打开位置」按钮，会打开资源管理器**并选中那个文件**。

默认下载目录是**程序目录下的 `downloads`**。如果你在设置里改过 `downloadDir` 又写了相对路径，
它是相对**启动时的工作目录**的——所以用 `.bat` 启动和自己 `cd` 到别处启动，可能指向不同地方。
想稳妥就写绝对路径。

### 文件名特别长 / 带一堆特殊字符

默认模板 `%(title).120B [%(id)s].%(ext)s` 已经把标题截到 120 **字节**（不是字符，
中文一个字约 3 字节），并会自动加 `[视频ID]` 后缀防重名。

嫌标题被截得看不全，可以在设置里改成 `%(uploader)s - %(title).80B [%(id)s].%(ext)s` 之类。
注意 Windows 单文件路径上限是 260 字符，标题太长+目录太深会直接下载失败。

### 点「打开位置」没反应

程序为此准备了 4 种打开方式的兜底（`cmd /c start` → `explorer` 直接调 → PowerShell →
剪贴板）。全失败时会把路径**复制到剪贴板**并提示你——直接粘贴到资源管理器地址栏就行。

## 六、升级与维护

### 「更新 yt-dlp」失败

升级走的是 pip，且固定使用阿里云镜像：

```
python -m pip install --upgrade yt-dlp bgutil-ytdlp-pot-provider -i https://mirrors.aliyun.com/pypi/simple/
```

失败通常是因为：网络不通镜像、或者 `runtime\python` 目录被占用（有下载任务在跑）。
**先停掉所有任务**再更新。

> 手动跑 `yt-dlp -U` 是**没用的**：pip 版会打印一句「请用 pip 更新」，
> 但退出码是 0，看起来像成功了。必须用上面的命令。

### 版本怎么判断新旧

yt-dlp 的版本号就是发布日期（`2026.10.26` = 2026 年 10 月 26 日）。超过 **45 天**没更新
就该升了——YouTube 的改动通常以周为单位。程序会在界面上亮黄标。

## 七、便携包相关

### 换电脑 / 放 U 盘能直接跑吗

可以。便携包里的 Node、CPython、ffmpeg、yt-dlp 全是随包的，不依赖系统环境变量，
所有路径按程序所在目录相对定位。

**有两个前提**：

1. **`.bat` 和 `.vbs` 必须保持 CRLF 行尾**——用 Git 检出、或某些编辑器另存时可能被改成 LF，
   cmd.exe 会解析异常。仓库的 `.gitattributes` 已经锁了 `eol=crlf`，手动改过文件要注意。
2. **别放在 OneDrive / 坚果云这类同步盘里**。几千个文件的实时同步会明显拖慢启动，
   而且 node_modules 那种深层目录容易触发同步冲突。

### 杀毒软件报毒 / 把文件吃掉

ffmpeg、node、python 这些是**未签名的第三方二进制**，某些杀软会误报（尤其对
「可执行文件 + 网络下载行为」的组合）。

处理：把整个程序目录加进杀软白名单，然后重新解压。程序本身只监听 `127.0.0.1`，
不对外暴露端口，也不向任何第三方服务器发送数据。

### 路径里有中文 / 空格

支持。`启动下载器.bat` 全套加了引号，Node 和 Python 侧都是按 `__dirname` 定位。
实测过放在「D:\我的 下载器\」这类带空格 + 中文的路径下正常工作。

## 八、还是不行

按这个顺序收集信息：

1. 跑 `scripts\check-deps.ps1`，把输出存下来
2. 双击 `_diagnose.bat`，它会生成 `_diagnose_result.txt`（环境变量、端口、文件清单）
3. 界面上失败的卡片 → 展开「原始报错（排查用）」→ 复制
4. 访问 `http://127.0.0.1:8808/api/env`，把 JSON 一起贴出来（里面是版本、路径、POT 状态）

这三样凑齐，问题基本能一眼定位。提交 issue 时请附上它们，并**去掉路径里的个人信息**。
